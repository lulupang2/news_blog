# Assembly Hall of Shame
CPU 성능 최적화를 위해서는 코드를 더 빠르게 돌리려고 노력하지만, Assembly Hall of Shame에서는 코드를 더 느리게 돌리기 위한 방법을 연구함 ㅋ

## 현재 챔피언
x86에서 fxrstor64를 사용하여 512바이트의 FPU/MMX/XMM 상태를 로드하고, 그 상태를 MMIO 지역에서 로드하여 CPU를 느리게 만들어 봄 ㅋㅋㅋㅋ
fxrstor64는 FXSAVE/FXRSTOR 명령어로 FPU/MMX/XMM 레지스터를 저장하고 복원하는 명령어임. 하지만 MMIO 지역에서 데이터를 로드해야 하므로 느릴 수 있어.

## 경쟁자
AMD Ryzen 7 5800H를 사용하여 fxrstor64 명령어를 실행했기 때문에 경쟁자로 인정 받음 ㅋㅋ

## 규칙
코드 최적화를 위한 규칙과 반대로 코드를 더 느리게 돌리기 위한 규칙을 정의함.
1. 코드는 하나의 명령어만 사용할 수 있음.
2. 코드는 인터럽트 될 수 없음.
3. 코드는 반복문을 사용할 수 없음.
4. 모든 플랫폼은 공장 출고 설정으로 사용해야 함.

## x86 리더보드
x86 리더보드는 현재까지 발견된 가장 느린 명령어를 표시하는 리더보드임.
리더보드의 1위는 현재 fxrstor64를 사용하는 코드가 차지하고 있음.

## fxrstor64
fxrstor64는 FXSAVE/FXRSTOR 명령어로 FPU/MMX/XMM 레지스터를 저장하고 복원하는 명령어임.
fxrstor64를 사용하여 MMIO 지역에서 데이터를 로드하면 CPU를 느리게 만들 수 있음.

## mov
mov는 CPU에서 가장 기본적인 명령어 중 하나로, 데이터를 이동시키는 명령어임.
mov를 사용하여 MMIO 지역에서 데이터를 로드하면 CPU를 느리게 만들 수 있음.

## vmovdqu
vmovdqu는 AVX 명령어 세트의 일부로, 128비트, 256비트, 512비트 데이터를 이동시키는 명령어임.
vmovdqu를 사용하여 MMIO 지역에서 데이터를 로드하면 CPU를 느리게 만들 수 있음.
