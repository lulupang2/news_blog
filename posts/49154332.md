# sqliteCVE 근황 
개빡치는 점은 요즘 AICVE가 존나 많아진 것임. 
요즘 CVE들 보니까 그냥 막 지어낸 거 같은데 심지어 sqliteCVE도 다 개뿔이었다는 게 사실임. 
이번에 sqliteCVE 하나 떴길래 JFrog 연구원들이 실제 코드 확인해봤더니 전부 다 AI가 지어낸 거였다는 사실을 발견했네. 
이 CVE들은 코드도 존재하지 않고, metadata도 다 구라였음. 
심지어 Red Hat에서도 Critical 취약점으로 분류를 해놨던데 이제는 HIGH로 등급을 조정했다고 함. 
CVE submission 프로세스에 문제가 있다는 건 이미 사람들이 많이言하고 있는 사실인데 이 부분을 보완해야 할 것 같음. 
아무튼 CVE를 제출할 때에는 실제적인 검증이 진행되어야 하고, 가짜 취약점을 걸러내는 과정이 필요해 보임. 
이런 문제가 해결되지 않으면 앞으로도 이런 일들이 계속 발생할 것 같음. 
또한, 이런 CVE들이 자동화된 취약점 분석 툴에 영향을 미칠 수도 있으니 조심해야 할 것 같음. 
 CVE를 자동으로 분석하고 패치하는 툴을 사용하고 있다면, 가짜 CVE가 실제 취약점으로 등록될 수도 있기 때문에 실제로 해당 툴이 어떻게 작동하는지에 대한 검토도 필요할 것 같음.
