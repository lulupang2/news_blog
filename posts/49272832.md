# 해결 과정
테일스케일에서 16년된 SQLite 버그 때문에 데이터베이스가 계속 부서져서 많이 당황했음. 6개월 동안 19번이나 부서졌대. 근데 이 버그 때문에 데이터가 다 날아가거나 하지 않았는데, 왜냐면 테일스케일이 컨트롤 플레인에서 데이터를 처리하는 방식이 신박하거든. 

# 컨트롤 플레인 아키텍처
테일스케일의 컨트롤 플레인은 여러개의 샤드(.coordination server)로 구성되어 있는데, 각 샤드가 SQLite 데이터베이스를 쓰고. 이 SQLite 데이터베이스에는 tailnet의 모든 정보들이 저장되어 있단다. 그리고 테일스케일에서 SQLite를 쓰게 된 이유는 간단함. SQLite가 유명하고, 안정적이고, 널리 사용되고 있으니까. 

# 문제 해결
근데 SQLite에 16년된 WAL-Reset 버그가 있었던거래. WAL-Reset 버그는 Checkpoint 과정에서 발생하는데, SQLite에서는 WAL 파일에서 데이터를 메인 데이터베이스 파일로 복사하는 것을 Checkpoint라고 함. 그런데 이 과정에서 데이터베이스 파일이 깨지는 문제가 발생하고. 테일스케일에서 이 버그를 해결하기 위해 SQLite 개발자와 함께 일했고, 결국 버그를 해결했다고 함.
