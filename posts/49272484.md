# 나의 에이전트 설정법

   2026년 8월 11일, 나는 내 에이전트 설정법을 작성하고 있다. 이는 인간이 작성한 것이며, 나의 gtm-에이전트가 일부를 검토하고 수정했지만, 나는 대부분의 수정을 되돌림. 이 글은 10배 더 많은 시간을 들여 작성했음. 결론은 'Has it been worth it?' 부분에서 확인할 수 있음.

   

   # 목표

   몇몇 사람들이 내 에이전트 설정법에 대해 물어왔지만, 먼저 목표에 대해 이야기해 보겠다. 나는 여러 제품과 비영리 단체를 운영하고 있다. 지금까지 언급된 제품은 The Daily FM 하나뿐이며, 이는 내가 원했기에 만들었던 것이다. 에이전트 실험의 목표는 적은 인원과 자원으로 여러 producto와 비영리 단체를 확장하는 것이다. 간단히 कह자면, 나는 에이전트 팀을 만들고 있는 중이다. 이는 약 한 달 전부터 시작한 것으로, 아직 초기 단계다.

   

   # 에이전트 프로필

   * ea-agent: 나의 행정 보조 エージェント로, 내가 기억해야 할 것을 상기시키고, 달력과 Linear gibi 툴을 관리한다.

   * ops-agent: 시스템 성능과 Sentry를 監視하고, 문제를 해결하거나 dev-agent에게 전달한다.

   * dev-agent: 나의 核心 개발자로, GitHub 액세스權을 가지고 있다.

   * gtm-agent: 나의 마케터로,	funnel, 트래픽 수, 소셜 미디어 등을 관리한다.

   * research-agent: 웹을 검색하고, dài期 비동기 연구를 수행하며, 보고서를 작성한다.

   * vps-agent: 나의 인프라 관리자로, 에이전트 박스의 루트 액세스 권한을 가지고 있다.

   

   # 런타임과 메모리

   모든 에이전트는 현재 Hermes 에이전트이며, 이는 SOUL.md, AGENTS.md, skill, 도구, MCP 서버, Mnemosyne 메모리 뱅크, 공유 Obsidian 위키 등으로 정의된다. 이는 이론적으로 모든 포터블이다.

   

   # 모델

   현재 모든 에이전트는 OpenAI GPT-5.6 Sol을 사용하며, GPT-5.6 Terra를 사용하여 서브 에이전트를 생성할 수 있다. 처음에는 Anthropic의 Fable을 사용했지만, API 청구서를 받고 Anthropic이 이 설정에 대한 구독 사용을 허용하지 않는다는 것을 알고 GPT로 전환했다.

   

   # 컴퓨팅

   6개의 에이전트는 간단한 DigitalOcean Basic Droplet에서 실행된다. 이는 4개의 vCPU, 8GB RAM, 160GB 디스크를 가지고 있다. RAM을 4GB에서 업그레이드해야만 했다. 왜냐하면 박스가 디스크에 스왑하기 시작했だから임. Tailscale로 보안을 유지하고, 공용 포트를 노출하지 않는다.

   

   # 코딩

   아직도 Claude Code와 Fable, Codex를 사용하지만, dev-agent도 있다. 나는 터미널에서 코드 변경과 이유를 실시간으로 관찰하는 것을 좋아한다. 나는... 이렇게 하면 불편하다.

   

   # 커뮤니케이션

   Buzz는 블록에서 만든 오픈 소스 슬랙 대안이며, 에이전트 지원이 첫 번째 클래스다. 아직 초기 단계지만, 많은 가능성이 있다. vps-agent는 새로운 에이전트를 생성하고 Buzz에 연결할 수 있다. 모든 에이전트는 DM에 응답하며, 룸에서는 호출이 필요하다.

   

   # 워크플로우

   이미 외부 시스템에서 Buzz로 메시지를 게시하는 웹훅을 설정했다. Buzz는 메시지를 형식화하고 특정 사용자를 호출할 수 있다.

   

   # 유즈 케이스

   자동화된 Sentry 응답, 간단한 개발 작업, 아침 업무 브리핑, 소셜 캘린더レビュー, 리마인더 및 연구, 일일 작업报告 등

   

   # 질문

   하나의 에이전트로 모든 것을 처리하는 이유는 무엇인가? 이는 쓸데없는일 처럼 보이지만, 주요 이유는 최소 권한이다. 일부 에이전트는 GitHub, 배포, 달력 액세스 권한이 필요하지 않다. 왜 블라스팅 반경과 잠재적인 실수를 증가시키려고 하는가?

   

   # 결론

   여정의 과정에서는 oui지만, ROI에는 nein임. 내가 이것들을 직접하는 것보다 10배 더 많은 시간을 들였음. 하지만, 팩토리를 구축하는 것은 아무것도 생산하지 않는다.
