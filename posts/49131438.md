# 새로운 MCP 프로토콜, 이게 정말革命적인 거임 ㄹㅇ 
시몬 윌리슨의 블로그에 새로운 포스팅이 올라왔는데, 이제는 MCP가 스테이트리스로 바뀌었다고 함. 이게 무슨 의미냐면, 기존에 두 번의 HTTP 요청이 필요했던 부분을 이제는 하나의 요청으로 처리할 수 있다는 거야. 

## 예전에比하면 진짜 편해졌네 
기존의 MCP는 initialize라는 메소드를 호출하고, 그다음에 tool/call이라는 메소드를 호출해야했어. 하지만 이제는 단 하나의 요청으로 처리할 수 있게 바뀌었고, 요청 본문도 훨씬 더 간단해졌어.
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "search",
    "arguments": {
      "q": "otters"
    },
    "_meta": {
      "io.modelcontextprotocol/clientInfo": {
        "name": "my-app",
        "version": "1.0"
      }
    }
  }
}
```
이 새로운 프로토콜은 클라이언트와 서버 모두에게 훨씬 더 간단하고 안전한 방식이야. 그리고 이제는 서버에서 세션을 관리해야 하는 복잡함도 없다 보니, 확장성도 훨씬 더 좋아졌어.

## mcp-explorer라는 새로운 툴도 나왔네 
이 툴은 MCP 서버를探索할 수 있게 해주고, 어떤 툴들이 지원되는지 확인할 수 있게 해 준다네. 다음과 같이 사용하면 되는데,
```bash
uvx mcp-explorer list https://agentic-mermaid.dev/mcp
```
이这样하면 해당 MCP 서버에서 지원하는 툴들을 보여준대. 그리고 툴 하나하나의 상세 정보도 확인할 수 있대.

## datasette-mcp도 있네 
이건 Datasette 플러그인으로, MCP 프로토콜을통해 Datasette 인스턴스에 접근할 수 있게 해 준다네. 그리고 지금까지 총 3개의 툴을 지원하고 있대. list_databases, get_database_schema, execute_sql이 바로 그것들임.

## 새로운 MCP 프로토콜은 기존보다 훨씬 더 나은 선택지 같음 
새로운 MCP 프로토콜은 기존의 복잡성과 상태 관리의 문제를 해결했다고 볼 수 있어. 그리고 확장성도 훨씬 더 좋아졌고, 안전성도 높아졌네. 그래서 앞으로 MCP를 이용한 개발에도 많이 활용될 것 같음.
