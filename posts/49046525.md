### fedora 45 버전 만들기 
요즘 리눅스 어떻게 되고 있는지 좀 알려줌. 
fedora 45 버전은 어떻게 만들어졌냐면, 
먼저 소스 코드와 패키지를 받아서 사용자들이 다운로드 받아 설치할 수 있는 아트팩트로 만드는 과정 임. 
이 과정은 패키지의 git push부터.iso, 클라우드 이미지, 컨테이너 이미지, ostree 배포 등 다양한 형태의 아트팩트를 만드는 과정임. 
이 글은 fedora 45 버전에서 어떻게 '소시지'를 만들었는지 설명하는 글이고, 
이 문서는 계속 업데이트될 예정이라 다음 버전이 출시되면 다시 업데이트될 예정임. 

### 패키지 시작점: dist-git
まず 페도라 프로젝트에서 패키지를 관리하는 곳은 dist-git임. 
여기서는 각 패키지의 소스 코드와 rpm spec 파일, 패치 파일 등을 Git 저장소로 관리함. 
패키지 제작자들은 fedpkg 라는 툴을 사용해서 Git 저장소를 관리하고, 
소스 코드와 패치 파일을 업로드하고, 빌드를 제출하고, 업데이트を作成하는 등의 작업을 함. 
fedpkg build 는 Git 저장소의 특정 커밋해시를 기준으로 빌드를 생성하기 때문에, 
빌드의 결과가 항상 재현 가능함. 

### 빌드 시스템: Koji
fedpkg build 로 빌드를 생성하면, Koji 라는 빌드 시스템이 takeover함. 
Koji 는 페도라 7 부터 사용된 빌드 시스템으로, 
 거의 모든 패키지를 빌드하는 역할을 함. 
Koji 의 아키텍처는 Hub-And-Spoke 모양으로, 
centralized 된 XML-RPC 서버와 PostgreSQL 데이터베이스를 사용함. 
Builder daemon 들이 작업을 polling 해서, 
 Mock chroot 환경에서 빌드를 수행하고, 
결과를 업로드함. 

### 업데이트 관리: Bodhi
Koji 에서 빌드된 패키지는 자동으로 사용자에게 전달되지 않음. 
Bodhi 라는 업데이트 관리 시스템을 통해서만 사용자에게 전달됨. 
Bodhi 는 사용자와 자동 테스트 시스템으로부터 피드백을 받고, 
업데이트를 테스팅 하는 과정으로, 
업데이트가 안정화되면 사용자에게 전달함. 

### 릴리즈 구성: Pungi
개별 패키지를 이용자에게 전달하는 과정은 Pungi 라는 툴을 사용해서 함. 
Pungi 는 다양한 아트팩트를 만들기 위해 사용되는 툴임. 
Pungi 는 Anaconda 라는 인스톨러를 이용해서, 
iso 이미지나 클라우드 이미지, 컨테이너 이미지 등을 만듦. 

### 이미지 빌드: Kiwi
Kiwi 는페도라에서 이미지 빌드를 위해 사용되는 툴임. 
Kiwi 는 xml 파일을 사용해서 이미지 정의를 하고, 
해당 이미지에 필요한 패키지를 설치하고, 
이미지를 빌드함. 
fedora 에서 Kiwi 를 사용해서 다양한 이미지들을 빌드하고 있음. 

### 이미지 빌드: Image Builder
Image Builder 는 페도라에서 ostree 기반의 이미지 빌드를 위해 사용되는 툴임. 
Image Builder 는 json 파일을 사용해서 이미지 정의를 하고, 
해당 이미지에 필요한 패키지를 설치하고, 
이미지를 빌드함. 
fedora 에서 Image Builder 를 사용해서 다양한 이미지들을 빌드하고 있음. 

개인적으로는 fedora 45 버전이 나오는데 요즘 리눅스 어떻게 되고 있는지 궁금했음. 
결론은 이렇게 패키지를 관리하고, 빌드하고, 업데이트하고, 릴리즈 구성하는 과정임. 
이번 버전에 새로운变化가 많은 것 같아서, 
다음 버전이 나올 때 다시 글 올릴 예정임.
