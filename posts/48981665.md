이제 웹어셈블리에서 GC랑 익셉션 지원이 기본값으로 활성化되서, wasmtime이 더 많이 발전했네. wasmtime 개발자들은GC랑 익셉션 지원 구현하기 위해 몇 년간 열심히 고생했음. 

#### 웹어셈블리 GC란?
원래 웹어셈블리 첫 버전에서는 객체와 참조 방식으로 작동하는 언어들이 웹어셈블리에서 작동하려고하면, 각 언어마다 별도의 垃圾수집기를 내장해야했어. 그래서 웹어셈블리 코드가 너무 커지고, 성능도 구리게 되었어. 

근데 이제 웹어셈블리 GC 제안 덕분에, structs, arrays랑 서브 타이핑 지원이 추가되었어. 구조체의 필드를 만들 때, struct.new 명령어를 사용하면 되고, 각 필드에 접근하기는 struct.get, struct.set 명령어를 사용하면 됨. 예를 들어, 이진 트리 노드 타입을 정의할 때는 이렇게 하면 되지:
```wasm
(rec (type $node (struct (field $key (mut f64)) (field $left (mut (ref null $node))) (field $right (mut (ref null $node))) (field $value (mut (ref null $payload))) ))
```
이렇게 하면 노드 구조체 타입의 새 인스턴스를 만들 때는 struct.new $node 라고만 해주면 되고, 노드의 특정 필드에 접근할 때는 struct.get $node $key, struct.set $node $left 이렇게 하면 되네.

#### 웹어셈블리 익셉션 지원
익셉션 제안도.gc랑 마찬가지로 웹어셈블리에서 익셉션을 사용하는 언어들을 더 지원하겠다는 목표를 가지고 있었음. 이 제안 덕분에 웹어셈블리는 익셉션을 사용하는 언어들을 더 잘 지원하겠지.

원래는 각 언어가 익셉션을 지원하려면 함수 호출에 익셉션 정보를 넣어서 반환하는 커스텀 호출 규약을 구현해야했어.근데 이 제안 덕분에 throw와 try/catch 문법이 추가되었고, 웹어셈블리 런타임이 익셉션을 더 쉽게 처리할 수 있게 되었어. 

### wasmtime의 GC 구현
wasmtime은 간단한 Cheney-style 세미스페이스 복사 垃圾수집기를 사용해. 이 垃圾수집기는 두 개의 세미스페이스로 나눠서 작동하고, 새로운 객체들은 항상 active 세미스페이스에 할당되네..gc가 일어날 때는 idle 세미스페이스에 있는 살아있는 객체들을 새로운 active 세미스페이스로 복사하고, 살아있는 객체들에 대한 참조를 새로 복사된 객체들로 업데이트 해줌. 

이 垃圾수집기는 웹어셈블리 linear memories를 이용해서 구현되어서, 웹어셈블리 런타임의 sandboxing 기능을 통해 메모리 안전성을 보장할 수 있어.
