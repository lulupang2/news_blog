# 인공지능, 이제 스스로 개선해 나간다는거임?  
최근에 인공지능 연구 개발이 엄청나게 빠르게 진행되고 있어. 특히 Anthropic, OpenAI 같은 연구소에서 나오는 연구成果가 감당 안되네...
일단 인공지능이 스스로를 개선하는 recursive self-improvement(자기 개선)이라는 개념은 1965년 I. J. Good이라는 사람이 제창했음. 
그는 **초지능 머신**이라는 걸 정의하면서, 인간보다 모든 지적 활동에서 뛰어난 성능을 보이면서 스스로를 개선할 수 있는 시스템이라고 했어.  
그 후에 Yudkowsky는 인공지능이 자기 자신의 지능을 개선하는 루프를 **recursive self-improvement**라고 이름 붙였지.  
이 루프는 인공지능이 자기의 현재 지능을 이용해서 자기 자신의 지능을 개선하는 거야. 
예를 들어 model이 자기 자신의 weight를 직접 개선하거나, 더 넓게 모델의 training pipeline과 deployment 시스템을 개선하는 거야. 
이런식으로 하면 모델의 후계자가 économiquement 가치 있는 task에서 더 뛰어난 성능을 보이도록 할 수 있어.  
근데 harness라는 게 중요한 역할을 해주는 거임. 
harness는 base model을surrounding하는 시스템으로, 모델이 어떻게 실행되고, 계획하고, 어떤ツール을 выз하고, 어떻게 행동하고, 어떻게 컨텍스트를 관리하고, 결과를 평가하는지 정의해 주는 거야. 
이 포스트는 harness 엔지니어링에 관해서 이야기해 볼거야.  
최근 연구에 따르면, **harness design patterns**라는 게 등장했어. 
이거는 agent framework랑은 살짝 다르지. 
agent = LLM + memory + tools + planning + action这样的 형태에서, 
workflow design, evaluation, permission control, persistent state management가 추가된거지. 
이러한 패턴을 설계할 때, simplicity와 genericness를 지키면서, 소프트웨어 엔지니어링의 지식을 활용해야 해.  
운영체제와 harness사이에도 유사성이 존재하지. 
즉, harness도 복잡한 로직을 캡슐화해서, interface를 간단하게 유지해야 해.

## Harness Design Patterns 
### 패턴 1: 워크플로 자동화 
モデル이 어떤 워크플로우를 통해 실행하고, 테스트하고, 반복하는지 정의하는 거임. 
karpathy의 autoresearch 레포ジ토리가 좋은 예시야. 
이 워크플로우는 goal-oriented 루프를 따르는 거야. 
plan -> execute -> observe/test -> improve -> execute again... 이런식으로 반복됨. 
근데 이과정에서, 유저한테 task specification이나 execution preference에 대한 클라리피케이션을 요청할 수도 있어.  
### 패턴 2: 파일 시스템을 활용한 영속적인 메모리 
long-horizon agent systems에서, simple control over rich states와 artifacts를保持하는 것이 중요해. 
harness는 모든 워크플로우와 로그를 컨텍스트에 담을 필요가 없고, files에 durable state를 유지하면 돼. 
예를 들어, experiment logs, code diffs, paper summaries, error traces, past rollout trajectories 같은 아티팩트들이 모델의 컨텍스트 윈도우보다 훨씬 길어질 수 있지. 
이러한 파일 시스템을 읽고, 쓰고,編集하는 건 LLM의 기본적인 스킬이야. 
그래서 핵심 모델의 기능을 개선하면, 파일 시스템에 대한 관리도 자연스럽게 улучш돼.  
## 케이스 스터디: 코딩 에이전트 하니스 
이제는 Claude Code, Codex, OpenCode, Cursor-style 에이전트같은 경우, 
mainstream coding agent의 인터페이스가 어느 정도 안착된 모습을 보이고 있어. 
코딩 에이전트는 개발과 디버깅을 위해 특정 레포지토리에 접근해서, 
파일을 발견하고, 읽고, 수정하고, 실행하는 과정을 자동화할 수 있어. 
근데 이 과정에서, 모델은 자기 자신의 실행 히스토리를 관리해야 해. 
이러한 Harness Layer가 모델의 핵심 지능과는 분리되어야해.  
근데 Harness Layer의 중요성은 앞으로 어떻게 발전할지 예측하기 어렵네...  
근데 near-term에서는, 핵심 지능의 직접적인 개선보다는, 
harness system을 meta-methodology로 발전시켜서, 
auto-research를 위한 모델의 self-improvement 루프를 만드는 것이 lebih 가능성이 크다구...  
这样하면, 모델은 harness system을 최적화하는 데에 집중할 수 있어. 
그리고 모델의 지능이 개선되면, 다시 harness system을 더 간단하게 유지할 수 있지...  
이러한 패턴과 기술들에 관해서 더 자세히 알고 싶으면, 
해당 연구 논문이나 레포지토리를 참조하기를 추천해...  
그리고 앞으로의 연구는 harnessシステム의 최적화와, 
모델의 지능 개선에 관해서 더 집중할 필요가 있을거 같아.
