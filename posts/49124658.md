### 데이터퓨전 사용기
데이터퓨전 사용해서 10억 규모 그래프 연산 가능함. 
일단 TLDR;는 데이터퓨전으로 그래프 맵리듀스 구현했음. 
가능한限 disk에 다 옮겨놓으니까 알고리즘도 블록 스캔에 의존하도록 설계했음. 
데이터퓨전이 스피로버, 소트머지 조인, 애그리게이션, 플랜ning, 실행 이런거 다 해주니까 코드는 가벼움. 
직접 테스트해봤는데 엄청난 메모리 제한 걸어봤는데도 잘 돌아감. 
물론 문제점들은 좀 있었음. 예를들면 극단적인 시나리오에서 데드락 생기는거나, SMJ에서 미리 정렬된 데이터 사용하는 방법을 못 찾겠음. 
그래도 돌아감. 
10GB 램으로도 10억 개 에지 그래프에서 페이지랭크 계산 가능함. 
Alternatively, 20억 개 에지 그래프에서 약결합성 분할 가능함. 
네트워크엑스나 이그래프 이런 라이브러리들은 이거 못함. 
이전에는 아파치 스파크나 그래프프레임즈 이런거 필요 줄 알았는데 지금은 아니라고 생각함. 
이젠 랩톱만 있으면 가능하다구요. 
### 테스트
两个 테스크를 테스트해봤음. 
- 페이지 랭크: 페이지 랭크 계산
  - 페이지 랭크는 그래프 상중심성 알고리즘 중 하나고, 검색 결과랭킹, 부정거래 탐지 이런데 많이 쓰임. 
  - 데이터퓨전 구현은 클래식한 프레겔: 벌크 동기화 병렬 알고리즘, 맵리듀스 같은 거로 구현함. 
  - 소트 머지 조인, 애그리게이션 이런거 사용해서 구현했음. 
- 약결합성 분할: 그래프의 약결합성 분할 찾기
  - 약결합성 분할은 핵심적으로 엔티티 해결 문제인거임. 
  - 다른 시스템에서 데이터 중복 제거할 때 전이 id로 그래프 구성하면 약결합성 분할 문제가 생김. 
  - 데이터퓨전 구현은 'in-database connected component analysis' 기반으로 함. 
  - 이 알고리즘은 스파크 그래프프레임즈 라이브러리에도 구현되어있었어서 당연히 선택함. 
### 결과
- 페이지 랭크: 간단했음. 
  - 소트 머지 조인 사용해서 확장성证明인데, 힙 조인도 가능함. 
  - 힙 조인 쓰면 더 빠름. 
  - 페이지 랭크는 유방향 그래프에서 돌아가니까 그래프를 대칭화 시킬 필요가 없음. 
  - 에지를 디스크로 옮겨놓고, 상태를 업데이트면서 디스크로 옮겨놓으면 라인지를 끊을 수 있음. 
  - 계산 시간은 오래 걸리는데, 15번 풀 이터레이션하는데 30분 걸림. 
  - 하지만 메모리 설정이 중요하지, 속도 설정이 중요하지 않음. 
  - 실제로 1억 그래프 애널리틱스같은 더 현실적인 숫자 넣으면 잘 돌아감. 
  - 실제로 구현해서 결과값도 확인했는데, 100% 일치함. 
  - 여기서도 아직 최적화 할 부분 많음. 
  - 에지를 범위별로 버켓팅하면, 소트 머지 조인이 에지 정렬을 매번 할 필요가 없음. 
  - fuse join+agg 이런거도 가능할 것 같음. 
- 약결합성 분할: 가장 어려웠음. 
  - 20억 개 에지 트위터 그래프가 이미 너무 큼. 
  - 에지를 대칭화 시키니까 최대 40억 개 에지까지 커짐. 
  - 8GB 데이터퓨전 풀로만해서 돌아감.
