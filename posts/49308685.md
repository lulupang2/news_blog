### GCC 16, 17에서 중첩 함수 쓰는법
그럼 GCC 16부터는 중첩 함수 쓰는법에 대해서 설명해 줌.
기존에는 중첩 함수를 사용하면 컴파일러에서 _trampoline_을 생성했는데, 
이 _trampoline_은 스택에 생성되어서 보안 상 문제가 있었음.
그래서 GCC에서는 중첩 함수를 사용할 때 _trampoline_을 힙에 생성하는 기능을 추가했는데, 
이 방법은 더 나은데도 메모리 할당 비용이 더 들고 롱임재프(longjmp) 사용 시 _trampoline_ 이 샤크됨 ㅋㅋㅋㅋㅋㅋ.
이런 문제를 해결하는 방법은 새로운 와이드 포인터 타입을 사용하는거임.
와이드 포인터란 128비트 이상의 포인터로 함수의 코드 주소와 Static Chain을 담을 수 있음.

### GCC 16
GCC 16부터는 중첩 함수에서 부모 함수의 변수를 접근하지 않으면 _trampoline_을 생성하지 않음.
예를 들어, 
```c
typedef int cb_f(int);
cb_f *foo(int x) { 
    int worker(int y) { 
        return x + y; // 캡처 O
    } 
    return worker; 
}
```
 이런 경우는 _trampoline_을 생성하지만,
```c
cb_f *bar(int _x) { 
    static int x; 
    x = _x; 
    int worker(int y) { 
        return x + y; // 캡처 X
    } 
    return worker; 
}
```
 이런 경우는 _trampoline_을 생성하지 않음.

### GCC 17
GCC 17부터는 중첩 함수에서 부모 함수의 변수를 접근해도 _trampoline_을 생성하지 않음.
예를 들어,
```c
typedef int cb_f(int y);
static int process(cb_f *cb, void *data) { 
    return __builtin_call_with_static_chain(cb(5), data); 
}
int main() { 
    int x = 7; 
    int worker(int y) { 
        return x + y; 
    } 
    return process(__builtin_call_code_address(worker), __builtin_call_static_chain(worker)); 
}
```
 이런 경우는 _trampoline_을 생성하지 않고, 자동으로 
```c
typedef int cb_f(int y);
int baz(void (*cb)(int), void *data) { 
    return cb(5); 
}
int foo(int k) { 
    int bar(int x) { 
        return k + x; 
    } 
    return baz(bar, NULL); 
}
```
 이와 같은 코드로 변환됨 ㅋㅋㅋㅋㅋㅋ.
