### C++ ABI란 뭔가요?
기본적으로 ABI란 이진 프로그램 모듈之间의 인터페이스 정도라고 할 수 있죠. 근데 막상 누가 묻길래 설명하기가 너무 힘든 거임. 그냥 위키에서는 이렇게 설명하고 있더라고요. 

근데 이게 사실 그렇게 틀린 설명은 아니죠. 그냥 정의를 설명하는 것 뿐이니까요. 그런데 이렇게 정의만 내리고 끝내버리면 좀 너무 빈약할 수도 있어요. 근데 실제로 컴퓨터과학은 그런 식으로 돌아감. 왜냐하면 엄청나게 엄격한 정의를 요구하지 않거든요. 

### CPU & OS
결국 어떤 이진 실행 파일이던지 특정한 CPU와 특정한 OS에서 돌아가잖아요. CPU 명령어셋이 다르면 이진 불호환성이 발생할 수 밖에 없어요. 예를 들어 ARM 프로세서에서 돌아가는 프로그램은 그냥 x64 프로세서에서 돌아갈 수 없으니까요. 

근데 CPU 명령어셋이 호환되는 경우에는요? 예를 들면 x64 프로세서는 x86 명령어셋을 지원해요. 그래서 x86 프로그램이 그냥 x64 운영체제에서 돌아갈 수 있는 거임? 이때 운영체제가 관여하게 돼요. 

갠적으로 CPU와 OS는 어떤 프로세서와 운영체제에서 돌아가는지를 결정하고, 오브젝트 파일 포맷, 데이터 표기 방식, 함수 호출 규약 같은 건 운영체제 수준에서 ABI 규약이라고 생각함. 

### 오브젝트 파일 포맷
그럼 동적 라이브러리를 어떻게 파싱할 수 있을까? 이때 오브젝트 파일 포맷 관련 ABI 규약이 관여하거든요. 

### 데이터 표기 방식
이번에는 파싱된 함수의 주소를 얻었으면, 이제 함수를 호출해야죠. 근데 함수를 호출하기 전에 매개변수를 넘겨야해요. 

### 함수 호출 규약
함수를 호출한다는 건 결국 함수의 시작 주소로 점프하는 거잖아요. 근데 함수를 호출할 때 매개변수를 넘겨주잖아요. 매개변수를 넘겨줄 때 레지스터나 스택을 사용할 수 있어요. 

근데 여기서 문제가 생기는데, 함수를 호출하는 쪽에서 레지스터를 사용해서 매개변수를 넘길 수도 있고, 스택을 사용해서 넘길 수도 있잖아요. 근데 함수를 정의하는 쪽에서는 스택을 사용해서 매개변수를 받을 수도 있고, 레지스터를 사용해서 받을 수도 있어요. 

그럼 함수 호출 규약은 뭘까? 함수 호출 규약은 함수의 매개변수를 넘길 때 어떤 규약을 따를 것인지 정의한 거예요. 예를 들면 매개변수의 전달 순서, 매개변수와 반환값을 전달할 때 어떤 레지스터나 스택을 사용할지, 함수 호출 전후에 어떤 레지스터는 바뀌지 않을지 등이 있어요. 

### 정리
사실 함수 호출 규약은 CPU 아키텍처마다 다를 수 있어요. 근데 x64에서는 대부분 시스템 V ABI를 따르거나 윈도우 x64 ABI를 따르는데, 둘 다 비슷비슷하다고 생각하면 됨.
