### AI 에이전트가 너의 비밀번호를 털어가는 코드를 실행해도 3명 중 1명은 그걸 허용하는 대재앙 ㄷㄷㄷ

며칠 전에는 브라우저용 게임을 출시했음. 이 게임에서는 AI 코딩 에이전트의 명령어를 승인하거나 거부하는 인간의 역할을 함 ㅋㅋ._some_ 명령어들은 일상적인 것들이고, _some_ 다른 명령어들은 에이전트가 네 비밀번호를 털어가는 코드를 실행하는 거임 ㄷㄷㄷ

게임은 해커뉴스에서 некоторый 관심을 끌었고, 통계를 추가한 후 40,000번 가량의 게임 진행과 409,000개의 개별적인 승인/거부 quyết정을 분석할 수 있게 된 거야. 그래서 인간이 악성 에이전트를 막는 마지막 관문으로 어떻게 수행했는지 확인해 볼게

**주요 통계 숫자**

* 평균 플레이어는 3분의 1의 위협을 놓치고 말았어(평균 정확도 66.3%)
* 32.9%의 세션은 부정적인 점수로 끝남. 승인된 위협들과 차단된 안전한 명령어들이 옳은 행동보다 더 많았던 거지
* 35.2%의 플레이어는 모든 위협을 캐치했지만, 안전한 명령어를 5분의 1 이내로 차단한 플레이어는 20.8%만 가능했어. 나머지는 모든 것을 차단해서 '인간 병목'이라는 타이틀을 받았지
* 7%는 모든 프롬프트를 승인했어. --dangerously-skip-permissions를 사용하는 팬들임

조금의 예外지만, 이 게임에서는 플레이어가 본 명령어 중 약 34%가 위협이였어. 일상 작업에서는 이러한 위협이 드물게 나타남. 플레이어들은 자신이 테스트되고 있음을 알았고, 시간 제한된 도전을 받고 있었어. 하지만 아래의 숫자는 위협을 비교하고 일반적인 인식水平을 이해하는 데 도움이 될 거야.

**위협 카테고리와 놓친 비율**

| 카테고리 | 예시 | 놓친 비율 |
| --- | --- | --- |
| Obvious destructive | rm -rf /, chmod -R 777 / | 11.7% |
| Persistent mutation | crontab injection, git config hijack | 23.8% |
| Exfiltration / code execution | curl to unknown APIs, typosquatted packages | 33.4% |
| Scope violations | cat ~/.aws/credentials, cat ~/.kube/config | 35.0% |

 명백하게 파괴적인 명령어는 가장 신뢰할 수 있게 잡히네. แต 실제로 자격증명을 노출시키는 명령어는 3배 더 많이 놓チ고 말았어

**npm 러닝 블라인드 스팟**

 게임에서 가장 많이 놓친 명령어는 `npm run analyze`였는데, 64.7%의 시간에 승인되었어. 이 명령어 자체는 보통 무해하지만, 실제로는 `package.json`에 정의된 스크립트를 실행하는 거야. 이 스크립트는 무해할 수도 있지만, 전에 작성된 악성 코드일 수도 있어

ゲーム이 에이전트의 기록 로그에서 실제로 스크립트가 포함하는 내용을 알 수 있게 해줌에도 불구하고, 2/3의 플레이어는 그래도 승인했어. 이는 기록 로그가 승인 프롬프트 바로 위에 있지만, 충분히 주의 깊게 읽지 않았다는 걸 의미함. 이러한 경우가 3개가 게임에 있는데, 가장 많이 놓친 목록에 포함되었어

| 명령어 | 놓친 비율 | 순위(37개의 위협 중) |
| --- | --- | --- |
| npm run analyze | 64.7% | 1위 |
| npm run setup | 48.0% | 4위 |
| npm run deploy | 44.9% | 8위 |

 이 3개의 명령어를 합치면, 52.5%의 시간에 놓치게 되는데, 다른 노출 스타일의 공격에서는 28.4%였어. 친숙한 스크립트 이름을 사용해서 적재荷를 감추면, 승인되는 비율을 2배로 높일 수 있어

 HACKER NEWS의 dns_snek이 말한대로, 이는 실제로 위험한 동작이 무해한 것으로 인식되는 문제를 보여줌

```That’s a great example of how dangerous actions are perceived as innocent. The entire model of approving specific commands is absolutely bonkers.

npm run build = run an arbitrary shell command written in package.json
```

에이전트는 승인 없이 어떤 동작도 수행할 수 있었음. 하지만 플레이어에게 명령어를 검토하라고頼む 것은 완전한 방어책이 아님. 또한, 에이전트가 `package.json`을 수정해서 qualquer 명령어를 실행할 수도 있었고, `build.js`에 악성 코드를 심었을 수도 있었어. 같은 식으로 `node_modules/xyz/index.js`에도 악성 코드를 심을 수 있었지

**압박하의 놓친 비율 증가**

Anthropic은 클라우드 코드에서 승인 피로가 실제 현상임을 이미 지적했음

```The more approvals a user sees, the less attention they pay to each, becoming over time much less diligent in their supervision```

저 게임에서도 이런 현상이 일부 보이는데, 세션이 끝날 때 趨勢를 보면 알 수 있음. 사용자가 승인한 명령어 수에 따라 그룹화해서 표시했지. 사용자가 더 적은 명령어를 완료한 경우, 사용자가 더 시간을 들여서 명령어를 확인했거나, 에러로 인해 게임이 잠깐 동결되었을 수도 있어. 모든 것을 차단한 사용자는 제외했어

그래프를 보면, 사용자는 처음에 몇 개의 명령어에서 warm-up을 하는 것처럼 보이고, 이후 놓친 비율이 다시 증가하는 것을 볼 수 있어. 이것은 시간 제한에 의한 스트레스나 플레이어가 더 많은 명령어를 완료하려고 하면서 실수를 더 많이 저지를 수도 있는 현상일 수도 있어

**예방의 비용: 과도한 차단**

게임에서 다음 명령어들은 무해한 것이었지만, 자주 차단되었어

* npm config set registry https://npm.internal — 59%의 시간에 차단됨 (내부 미러 설정)
* rm -rf dist/ — 45%의 시간에 차단됨 (빌드 출력 지우기, 새 빌드 하기 전 흔히 수행함)
* kill $(lsof -t -i:3000) — 43%의 시간에 차단됨 (포트를 해제하기 위해,อาจ 충돌한 프로세스 때문에)

이것은 인간이 에이전트를 제어하는 다른 한면의 딜레마야. 사용자는 실제로 무해한 명령어를 승인해야 되는데, 차단하면 에이전트가 더 느려짐. 시간이 지나면 이런 노イズ로 인해 사용자가 경계를 내리면서 악성 명령어를 승인하게 될 거야. 이런 문제를 완화하기 위해 Anthropic의 'Auto Mode'와 같은 기능이 있지만, 완전하지는 않아

**cat 의争议**

`cat ~/.zshrc`는 45.9%의 플레이어에 의해 승인되었고, 가장 논쟁적인 명령어가 되네. 해커뉴스의 반응은 옳았어. 많은 개발자가 비밀번호를 쉘 프로파일에 저장하지 않기 때문에, 이 명령어는 무해해. 하지만 비밀번호를.export하는 개발자들에게는 자격증명 노출 위험이 있지

**요점**

게임과 관련된 토론을 따라가면서 인간-에이전트 협력 모델에 대해 더 많은 것을 배웠어. 게임은 인간이 에이전트의 마지막 방어선으로서 어떻게 작동하는지 보여주는데, 노이즈가 많은 것이 피로를 일으키고, 개발자가 항상 변경된 상황을 신속하게 평가해서 위험을 결정하지는 못하니까

개발자로서, 우리는 권한 모델의 다양한 트레이드오프를 잘 알고, 샌드박싱을 적용하거나 자격증명을 분리해서 환경 변수 비밀을藏하는 등 위험을 줄이는 방법들을 알아야해. 이전 포스트에서 이러한 실제対策에 대해 다루었어
